System Operations Toolkit

View repository on GitHub →

Objective

The objective was to build a practical Linux and Bash operations toolkit for common system-administration checks: disk usage, system health, log inspection, path-specific usage, and backups.

Problem addressed

Linux systems generate useful operational signals, but those signals are only helpful if they can be inspected consistently. These scripts turn routine checks into small, repeatable commands.

Implementation

  • disk_usage.sh monitors disk usage across partitions and warns when usage exceeds 80%.
  • system_health.sh checks CPU, memory, and disk status and displays OK or WARNING states.
  • log_analyzer.sh counts total log lines, identifies errors and warnings, and displays the last five lines.
  • check_path.sh checks disk usage for a user-supplied path.
  • backup.sh copies shell scripts into a timestamped backup directory.
  • arguments_practice.sh, functions_practice.sh, and hello_system.sh cover Bash arguments, reusable functions, and environment variables.
  • The README states that GitHub Actions runs syntax checks and ShellCheck when code is pushed.

Technical decisions

  • Each script has a narrow responsibility, making it easier to read, test, and reuse.
  • The 80% threshold gives a simple, explicit warning condition.
  • ShellCheck provides automated static analysis for common Bash mistakes.
  • GitHub Actions turns script quality checks into a repeatable CI step.

What I learned

I learned how to structure Bash scripts with arguments and functions, inspect system resources from the command line, and use CI to catch basic scripting issues before they reach a repository’s main branch.

Current limitations

  • This is a practical operations toolkit, not an enterprise monitoring platform.
  • The exact AWS EC2 deployment process mentioned in the README could not be independently verified in this build.
  • The scripts are intended for learning and light operational use rather than large-scale fleet monitoring.

Future improvements

  • Add unit-style tests for script behaviour.
  • Support configurable thresholds through arguments or environment variables.
  • Emit machine-readable output such as JSON for integration with other tools.
  • Add alerting or notification integration where appropriate.
