Docker System Health Monitor

DockerDockerfileUbuntuBashLinux monitoring

View repository on GitHub →

Objective

The objective was to package a Linux system health-monitoring script into a custom Docker image, demonstrating how a script and its runtime dependencies can be distributed as a container.

Problem addressed

A monitoring script may work on one machine but fail on another because of missing dependencies or configuration differences. Containerizing it makes the execution environment more consistent.

Implementation

  • The repository contains a Dockerfile, README.md, check_path.sh, and system_health.sh.
  • The image uses Ubuntu as its base image.
  • system_health.sh checks CPU, memory, and disk usage.
  • The script reports warning conditions when usage exceeds 80%.
  • check_path.sh accepts a path argument and checks disk usage for that path.
docker build -t system-health:v1 .
docker run system-health:v1

Technical decisions

  • Ubuntu provides a familiar Linux base for running Bash-based system checks.
  • The Dockerfile packages the script with its execution environment.
  • A versioned image tag, system-health:v1, makes the built image easier to identify.

What I learned

I learned how a Dockerfile turns a script into a portable image, how docker build and docker run fit into that workflow, and how containerization can reduce environment differences.

Current limitations

  • This is a containerization and system-monitoring exercise.
  • This repository does not contain a Docker Compose file; it should not be confused with the separate Compose project.
  • The monitor reports local container or host-level signals depending on how it is run; it is not a full observability platform.

Future improvements

  • Add configurable thresholds and output formats.
  • Run the container with explicitly defined capabilities and read-only filesystem settings where practical.
  • Add automated image build checks in CI.
