View repository on GitHub →

Objective

The objective was to learn Infrastructure as Code by provisioning an AWS EC2 instance using Terraform rather than creating it manually in the AWS Console.

Problem addressed

Manual cloud setup is difficult to reproduce and easy to drift from. Terraform makes the intended infrastructure declarative: the configuration describes the required resources, and Terraform plans and applies changes against that description.

Implementation

  • The repository includes main.tf, variables.tf, outputs.tf, .terraform.lock.hcl, and a README.
  • The configuration uses the AWS provider and provisions an EC2 instance.
  • The README documents the AWS region as ap-south-1 and the instance type as t3.micro.
  • Resource tags are part of the configuration.
  • The README covers terraform init, plan, apply, and destroy.
  • The project introduces Terraform state and how Terraform tracks managed resources.
terraform init
terraform plan
terraform apply
terraform destroy

Technical decisions

  • Separating variables.tf and outputs.tf keeps configuration inputs and resulting values explicit.
  • The lock file helps make provider versions more reproducible.
  • Using a small instance type keeps the learning project inexpensive.
  • Tags make AWS resources easier to identify.

What I learned

I learned how Terraform translates configuration into a plan, how state records the resources Terraform manages, and why a plan should be reviewed before an apply. I also learned that Infrastructure as Code is as much about repeatability and review as it is about creating resources.

Current limitations

  • This is an Infrastructure as Code learning project.
  • Security Groups, remote S3 state, and other advanced configuration should be verified directly in the repository before being described as implemented.
  • No measured provisioning-time improvement is claimed, since that would require evidence.

Future improvements

  • Add a dedicated Security Group with explicit ingress rules.
  • Use a remote S3 backend with state locking.
  • Add automated terraform fmt, validate, and plan checks in CI.
  • Introduce multiple environments through workspaces or directory structure.
