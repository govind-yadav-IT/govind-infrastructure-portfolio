Objective

The objective was to use Docker Compose to define and run more than one container as a coordinated local application environment.

Problem addressed

Running several containers manually requires separate commands, port mappings, and configuration. Docker Compose allows services, networks, ports, and volumes to be declared in one Compose file.

Implementation

  • Nginx serves a portfolio webpage.
  • The web server is exposed on localhost port 8080.
  • A System Health Monitor runs as a separate service.
  • Docker Compose manages the services.
  • The project demonstrates service configuration, container networking, port mapping, and volume mounting.
Verification note: the exact service dependencies, health-check configuration, and runtime behaviour should be confirmed from the repository’s Compose file and README. This case study intentionally avoids inventing service definitions.

Technical decisions

  • Separating the web server and health monitor demonstrates a multi-service Compose setup.
  • Port mapping makes the Nginx service reachable from the host on port 8080.
  • Volume mounting allows web content to be supplied without baking it into the image.
  • Compose provides a single declarative entry point for starting the application stack.

What I learned

I learned how Docker Compose expresses multi-container applications, how containers communicate over Compose networks, and how ports and volumes connect containers to the host filesystem and host network.

Current limitations

  • This is a local container-orchestration learning project.
  • It is separate from both the Docker health-monitor repository and the Infrastructure Delivery Platform.
  • Production concerns such as secrets management, resource limits, and persistent storage are not claimed as implemented.

Future improvements

  • Add explicit service health checks and dependency conditions.
  • Use named volumes and documented network configuration.
  • Add Compose overrides for development and production-style local environments.
